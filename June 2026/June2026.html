Changelog

Redesigned Resource Discovery (Preview)! One of the first steps in any Chameleon experiment is discovering what hardware fits your needs. The current Resource Discovery application has served Chameleon users well since the project began, but it has shortcomings: for example, it doesn’t include availability information for a node (i.e., when you can actually make a reservation). This month, we are excited to announce a brand new Resource Discovery browser with a completely updated interface. This interface now lets you filter by availability, and improves the overall experience of filtering for specific hardware properties. Additionally, it’s now easier to compare usage between sites, letting you plan for both large scale experiments, and experiments where you want to renew a lease. This browser is still in preview, but please contact us via the Help Desk with any questions for feedback. Stay tuned for VM instance support in the future.

Support for ccauth in python-chi. Last month, we released ccauth as a new method for authenticating with the CLI via a “device flow,” meaning that instead of setting up environment variables with credentials, you instead open a link in your browser. This month, we’ve added this same authentication method to python-chi via the use_device_auth function. If you have the latest version of python-chi installed, and you install ccauth via pip, you can simply call context.use_device_auth() at the top of your script to set up credentials. No more messing around with openrc files or a clouds.yaml config!

Improved long-running commands on CHI@Edge. Our edge testbed, CHI@Edge, allows users to run containerized workloads on devices, including Raspberry Pis and Nvidia Jetson Nanos. While typically you will want to run your experiment as the container’s command, it is also possible to execute one-off commands for debugging, like ls, ps, etc. These one-off commands would timeout if they took a while to execute. This month, we’ve improved this, so that you can also run long running commands like bash or apt-get update inside your container. Right now, you can run these commands via the CLI using openstack appcontainer exec --interactive

Vendor-data removal. Back in March, we deprecated our vendor-data service which automatically configured new instances with credentials. This month, we’ve stopped the service at our sites. If you need to authenticate from within your instance, see our new documentation on the topic. Importantly, if your experiment automatically orchestrates Chameleon resources from an instance (e.g., if you have a script which provisions an instances, runs an experiment, and uploads data), you will now need to provide your own application credential. For any questions or concerns, please contact us via the Help Desk.

Documentation improvements. We've refreshed the CLI, KVM, Trovi, and federation guides with clearer troubleshooting, cross-references, and python-chi examples — check out the updated docs for a smoother experience with your Chameleon workflows.

Kate Keahey Keynotes ISC High Performance 2026 Reproducibility Workshop

Chameleon Cloud PI Kate Keahey delivered a keynote at the 1st Workshop on Sustainable Practices for Reproducibility in HPC (REPRO-HPC), held June 26 at ISC High Performance 2026 in Hamburg, Germany. The workshop, co-located with ISC26, tackled the reproducibility challenges facing HPC and systems research — complex software stacks, cutting-edge hardware, and costly experiments — themes central to Chameleon's own Trovi reproducibility work. Keahey shared the keynote slot with Helena Vela Beltran of Do IT Now (EESSI). Argonne coverage | HPCwire coverage
